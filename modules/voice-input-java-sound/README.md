# voice-input-java-sound

마이크에서 한마디를 받아 WAV 로 만듭니다. `AudioCapturePort` 의 Java Sound 구현입니다.

## 공개 API

| 타입 | 하는 일 |
|---|---|
| `MicrophoneCapture` | 마이크를 열어 한마디를 녹음합니다. 장치를 고를 수 있습니다 |
| `UtteranceDetector` | 말이 시작되고 끝난 것을 소리 크기만 보고 판단합니다 |

## 의존성

`voice-input-api` 와 JDK 의 `javax.sound.sampled` 만 봅니다. JavaFX, HTTP,
`voice.http` 를 import 하지 않습니다 — 마이크는 소리만 알면 됩니다.

## 형식

16kHz · 16비트 · 모노로 받습니다. whisper 가 이 형식으로 학습돼 있어서, 더 좋은 품질로
받아도 인식이 나아지지 않고 서버가 다시 변환하게 될 뿐입니다.

## 말이 끝난 것을 알아채는 법

정해진 시간을 꽉 채워 녹음하면 명령 하나에 녹음 대기까지 얹혀 느려집니다. 그래서 말이
그친 것을 알아채고 끊습니다.

문턱값은 고정하지 않습니다. 조용한 방과 카페의 배경 소음이 열 배 넘게 차이 나서,
고정하면 한쪽에서는 말을 못 알아채고 다른 쪽에서는 영영 안 끊깁니다. 처음 300밀리초를
배경 소음으로 재고 그보다 훨씬 큰 소리만 말로 칩니다.

다만 배경 소음에 **상한**을 둡니다. 사람은 단추를 누르자마자 말하기 때문에, 배경을 재는
그 300밀리초에 말소리가 섞여 들어가 배경이 실제보다 크게 잡힙니다. 그러면 문턱이 따라
올라가 진짜 말이 조용한 것으로 보이고, 말하는 도중에 끊깁니다. 실제로 2.6초짜리 발화가
1.6초만 녹음됐고, 인식기는 그 토막에 대고 엉뚱한 말을 지어냈습니다.

## 판단을 따로 뺀 이유

`UtteranceDetector` 는 소리 장치를 모릅니다. 크기 값을 순서대로 넣어 주면 상태가 바뀝니다.

말하다 숨 쉬는 것으로 끊기거나, 조용해진 뒤에도 계속 녹음하거나, 첫 음절만 담고 끝내는
것은 **모두 오류를 내지 않습니다.** 사람이 마이크에 대고 말해 봐야만 드러납니다. 그래서
마이크 없이 검사할 수 있게 갈라 두었습니다.

## 장치를 고를 수 있는 이유

자바가 고르는 기본 장치가 운영체제의 기본을 따라가지 않습니다. 실측에서 자바 기본은
소리가 하나도 들어오지 않는 "주 사운드 캡처 드라이버" 였고, 사용자가 실제로 쓰던
이어폰은 목록의 다른 자리에 있었습니다.

```java
var microphone = new MicrophoneCapture();
microphone.devices();                       // 고를 수 있는 장치 이름
microphone.useDevice("마이크(Realtek)");     // 비우면 기본 장치
```

블루투스 이어폰은 연결이 끊깁니다. 정해 둔 장치가 사라지면 기본으로 돌아가되,
`fellBackFrom()` 에 그 사실을 남깁니다. 조용히 바꾸면 사용자는 왜 갑자기 안 되는지
알 수 없습니다.

## 마이크가 안 잡힐 때

`tools/MicMeter.java` 가 장치별로 소리 크기를 실시간 막대로 보여 줍니다. 빌드를 거치지
않고 바로 돌아갑니다.

```powershell
java tools\MicMeter.java        # 기본 장치
java tools\MicMeter.java 2      # 목록의 2번
```

실제 마이크로 녹음해 WAV 로 남기는 확인은 평소 검사에서 빠져 있습니다.

```powershell
./gradlew.bat :modules:voice-input-java-sound:test --tests "*MicrophoneProbe" "-Dvoice.mic=record"
```

## 비목표

- 인식하지 않습니다. WAV 를 만들어 넘길 뿐입니다.
- 소리를 파일로 남기지 않습니다. 메모리에서 바로 넘깁니다.
- 계속 듣지 않습니다. 한 번 부르면 한마디만 받습니다.
