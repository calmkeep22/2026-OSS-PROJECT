# ai-insight-api

AI 분석 계약. 값과 포트만 있고 구현은 없습니다.

## 공개 API

| 타입 | 하는 일 |
|---|---|
| `AiInsightPort` | 한 종목 분석을 받아 옵니다 |
| `NewsPort` | 뉴스와 질의응답을 받아 옵니다 |
| `AiInsight` | 분석 결과 전체. 함께 전해야 하는 단서를 스스로 셈합니다 |
| `Forecast` | 다음 거래일 예측. 검증을 통과했는지를 값에 싣습니다 |
| `AnomalySignal` | 이상 움직임과 위험도 |
| `SimilarStock` · `SimilarOutlook` | 닮은 차트와 그 구간 다음에 있었던 일 |
| `NewsDigest` · `NewsArticle` | 기사와 사건과 감성 지수 |
| `ChatAnswer` | 질문 하나에 대한 답과 근거 |
| `Confidence` | 신뢰도. 알려야 하는 수준인지 스스로 압니다 |
| `AiUnavailableException` | 받지 못했을 때. 사용자에게 그대로 보여 줄 문장을 담습니다 |

## 의존성

`finance-domain` 만 봅니다. 어떤 엔진이 어디서 도는지 알지 못합니다.

JavaFX, HTTP 클라이언트, JSON 라이브러리를 import 하지 않습니다. `verifyModuleBoundaries`
가 막습니다.

## 이 모듈이 지키는 것

**단서를 화면이 고르지 못하게 합니다.** `AiInsight.requiredCaveats()` 가 함께 전해야 하는
문장을 전부 돌려줍니다. 신뢰도가 낮다는 사실, 방향 예측이 검증에서 우연과 구별되지
않았다는 사실, 닮은 차트가 예측이 아니라는 사실이 여기 들어 있습니다.

숫자와 단서를 따로 주면 화면이 숫자만 보여 줄 수 있습니다. 화면을 볼 수 없는 사용자는
그 숫자를 얼마나 믿어야 하는지 알 방법이 없습니다.

**없는 값을 지어내지 않습니다.** 받지 못한 것은 `Optional` 이고, 화면은 그 자리를 비우는
대신 받지 못했다고 적습니다. `SimilarOutlook.hasCounts()` 처럼 "0건 0건" 과 "세지 않았음"
을 구별하는 메서드가 여럿 있습니다.

**서비스가 쓴 문장을 우리가 고쳐 쓰지 않습니다.** `SimilarOutlook.disclaimer` 와
`note` 는 분석 서비스가 준 그대로입니다. 같은 뜻으로 바꿔 쓰면 무엇이 서비스의 주장이고
무엇이 우리 해석인지 사용자가 구별할 수 없습니다.

## 비목표

- 분석을 직접 하지 않습니다. 모델도 규칙도 여기 없습니다.
- 사고팔라고 하지 않습니다. `ChatAnswer.declined` 는 실패가 아니라 답하지 않기로 한 것입니다.
- 값을 저장하지 않습니다. 캐시는 서비스 쪽에 있습니다.
