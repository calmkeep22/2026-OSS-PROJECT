# accessible-investor — AI 엔진

저시력자·시각장애인용 주식 정보 도구의 **AI 파트**.
소리 변환·음성 안내·UI는 다른 담당이 맡으므로 이 저장소에 없다.

세 가지를 한다.

| 파트 | 하는 일 | 상태 |
|---|---|---|
| [**이상감지 · 위험도**](results/01_anomaly/) | 장중 이상 움직임 탐지, 종목별 진입 난이도 | **작동** — 규칙 기준선 대비 PR-AUC 3.0배 |
| [**차트 유사도**](results/02_similarity/) | 1·3·6·12개월 네 창에서 닮은 구간 검색 | **작동** — 4성분 재순위 |
| [**다음날 예측**](results/03_forecast/) | 방향·변동성 예측 + 급락 반등 신호 | **급락 반등만 검증 통과** |

## 빠른 시작

```bash
pip install -r requirements.txt
```

### ① 바로 써 보기 — 아무 종목이나

`models/` 에 필요한 파일이 다 들어 있어 **clone 직후 바로 돈다.**

```bash
python cli.py serve health           # 배포 파일 점검
python cli.py serve predict 카카오    # 다음 거래일 예측
python cli.py serve anomaly 알테오젠   # 이상 움직임 + 위험도
python cli.py serve similar NVDA     # 닮은 차트 종목
```

### ② 연구 결과 재현하기

```bash
python cli.py backfill-news --days 365
```

뉴스를 **먼저** 모은다. 이걸 건너뛰면 뉴스 열이 최근 며칠만 차서 사실상
상수가 되고, 모델이 뉴스에서 배울 것이 없어진다. 한 번만 돌리면 되고
그 뒤로는 `python cli.py collect-news` 로 하루치씩 얹는다.

```bash
python cli.py results
```

끝나면 **[`results/index.html`](results/index.html)** 을 브라우저로 열면 된다 (서버 불필요).

## 트레이딩 툴에 붙이기 — 임의 종목 서비스

위쪽은 **연구·검증** 경로다. 38종목 표본에서 성능을 재고 그 근거를 남긴다.
실제 도구에 올릴 때는 아래 함수 셋을 쓴다. **코스피·코스닥·나스닥·S&P500
6,228종목 아무거나** 받는다.

```python
from accessible_investor import serving as SV

SV.warm()                              # 기동 시 한 번 (약 3초)

SV.predict("035720", bars=kiwoom_df)   # 다음 거래일 예측
SV.anomaly("035720", bars=kiwoom_df)   # 이상 움직임 + 위험도
SV.similar("035720", bars=kiwoom_df)   # 닮은 차트 종목
```

커맨드라인에서도 그대로 확인된다.

```bash
python cli.py serve predict 카카오
python cli.py serve health
```

**연동 방법은 [`INTEGRATION.md`](INTEGRATION.md) 에 따로 정리했다** —
봉 데이터 형식, 응답 스키마, 오류 코드, 운영 주기까지.

### 연구용 코드를 서비스로 바꾸며 푼 문제 셋

원래 구조는 **조회 시점에 그 종목 과거로 모델을 새로 학습**했다. 연구에서는
맞지만 증권 툴에서는 세 가지가 동시에 막힌다.

| 막던 것 | 원인 | 해법 |
|---|---|---|
| 38종목 밖은 `KeyError` | 평가용 유니버스로 종목을 찾았다 | [`registry.py`](accessible_investor/registry.py) — 6,228종목 목록을 따로 둔다 |
| 상장 1년 반 미만은 예측 불가 | 종목당 학습 표본 250행이 필요했다 | [`pooled.py`](accessible_investor/pooled.py) — 미리 학습해 두고 조회 시엔 확률만 계산 |
| 조회마다 7초 · 이웃 풀 수집 | 매번 학습 + 비교군 조회 | [`reference.py`](accessible_investor/reference.py) — 비교군을 분위수로 굳혀 저장 |

핵심은 **피처가 이미 종목 중립**이라는 점이었다. 32개가 전부 무차원 값
(수익률·이격률·RSI·베타·지수 대비 초과)이라 삼성전자 행과 NVDA 행이 같은
척도다. 그래서 그냥 쌓아 한 번 학습하면 된다 — 종목당 1,470행이던 학습
표본이 **153종목 263,277행**이 됐다.

| | 종목별 재학습 | 파운데이션(풀드) |
|---|---|---|
| 학습 시점 | 조회할 때마다 | 미리 한 번 (분기 1회) |
| 학습 표본 | 그 종목 1,470행 | 153종목 **263,277행** |
| 조회 지연 (실측) | 7,000ms | **167ms** |
| 최소 자료 | 250봉 (없으면 거절) | 30봉 (짧으면 저신뢰 응답) |
| 대상 종목 | 유니버스 38 | **6,228** |

성능 비교는 아래 「무엇이 맞고 무엇이 안 맞는가」에 같은 표로 실었다 —
같은 38종목 × 40거래일에서 두 방식을 나란히 쟀다.

### 정말 아무 종목이나 되는지 — 무작위 20종목 실측

네 지수에서 시드 고정으로 5종목씩 뽑아 세 기능을 다 돌렸다. **학습 풀
153종목에도, 평가 유니버스 38종목에도 없는 종목들**이다.

| 지수 | 표본 | 예측 | 이상감지 | 유사도 |
|---|---|---|---|---|
| KOSPI | 5 | 5/5 | 5/5 | 5/5 |
| KOSDAQ | 5 | 5/5 | 5/5 | 5/5 |
| NASDAQ | 5 | 5/5 | 5/5 | 5/5 |
| S&P500 | 5 | 5/5 | 5/5 | 5/5 |

**60건 전부 성공, 예상 못 한 실패 0건.** 워밍업 후 국내 예측은 180~190ms,
이상감지 25~35ms, 유사도 20~24ms 다 (표에 보이는 큰 값은 첫 조회에서
시세를 새로 받는 시간이다).

## 무엇이 맞고 무엇이 안 맞는가

이 저장소의 핵심 메시지다. 전부 **38종목 × 40거래일 = 1,520건 워크포워드**로
측정했고, 지표는 **균형정확도**(쏠림이 얼마든 50%가 진짜 무작위)다.

모델은 **앙상블 하나로 확정**했다. 타깃마다 각자의 최고 모델을 고르게 두면
비교가 성립하지 않는다 — 변동성은 앙상블, 방향은 로지스틱이 뽑혀 **서로 다른
모델끼리 견주는 표**가 나갔었다. 차이가 타깃 때문인지 모델 때문인지 알 수 없다.

| 시도 | 결과 | 판정 |
|---|---|---|
| 다음날 **변동성** (전체 피처 · 앙상블 · 종목별) | **54.73%** [52.2, 57.2] · 28/38종목이 50% 초과 | **검증 통과** |
| 다음날 **변동성** — **배포 모델(파운데이션)** | **53.23%** [50.61, 55.77] · 26/38종목 | **검증 통과** |
| **급락 후 반등** (\|z\|>3) | **+4.94%p** (날짜 단위 보정 후) · 561일 | **검증 통과** |
| 다음날 **방향** (같은 앙상블) | 50.38% [47.9, 52.9] · 16/38종목 | 미검증 |
| 국내 뉴스+가격 (139종목) | 균형정확도 0.538 | 미검증 |
| 해외 100종목 × 4년 (30조합) | 최고 HR 0.5127 < 무지성 0.5167 | 미검증 |
| 뉴스 교차언어 전이 (미국→한국) | ROC-AUC 0.5047 | 미검증 |

**방향은 신뢰구간이 50%를 품는다.** 24개 조합을 전수 측정했는데 단 하나도
하한이 50%를 넘지 못했다. 반면 변동성은 9개 조합에서 넘었다.

### 모델을 왜 앙상블로 정했나

같은 워크포워드(1,520건)를 모델별로 나눠 본 것이다. 감추지 않고 전부 싣는다
(`model_by_target.csv`).

| 모델 | 변동성 | 방향 | 건당 지연 |
|---|---|---|---|
| **앙상블** | **54.73%** [52.2, 57.2] ✅ | 50.38% | 4.0초 |
| 로지스틱회귀 | 52.09% | 50.77% | 0.15초 |
| 랜덤포레스트 | 52.07% | 50.39% | 0.83초 |
| 그래디언트부스팅 | 51.10% | 49.58% | 3.3초 |

**주력 타깃(변동성)에서 앙상블만 50%를 유의미하게 넘는다.** 방향에서는
로지스틱이 0.4%p 높지만 어차피 넷 다 미검증이라 우열을 가릴 근거가 없다.
그래서 검증을 통과한 타깃에서 이긴 모델로 정하고, **양쪽을 그 모델로 잰다.**

건당 4초를 감수하고 앙상블을 고른 판단이다 (`forecast.LATENCY_FREE_MS = 1000`).

**여기까지는 연구 경로의 결론이다.** 실제 배포는 이 앙상블을 종목마다 다시
학습하지 않고 **미리 학습해 굳힌다** — 지연이 167ms 로 떨어지고 모든 종목이
대상이 된다. 바로 아래에서 두 방식을 같은 조건으로 잰다.

### 파운데이션 모델은 종목별 재학습만큼 맞는가

서비스로 올리려면 **조회 시점에 학습하는 구조를 버려야** 했다. 그래서 153종목
263,277행을 한꺼번에 학습해 모델 하나로 굳혔다. 문제는 **그게 더 맞는다는
보장이 없다**는 것이다 — 표본이 179배가 되는 이득과 종목 고유의 버릇이 평균에
묻히는 손해 중 뭐가 큰지는 재 봐야 안다.

같은 38종목 × 40거래일 **교집합 1,443건**에서 나란히 쟀다
(`pooled_vs_perstock.csv`).

| 타깃 | 방식 | 균형정확도 | 95% 신뢰구간 | 판정 | 50%초과 | 학습표본 |
|---|---|---|---|---|---|---|
| 변동성 | 종목별 재학습 | **55.65%** | [53.05, 58.17] | 검증 통과 | 27/38 | 1,486행 |
| 변동성 | **파운데이션(풀드)** | **53.23%** | [50.61, 55.77] | **검증 통과** | 26/38 | 258,363행 |
| 변동성 | **파운데이션 — 미학습 종목** | **53.24%** | [50.68, 55.78] | **검증 통과** | 25/38 | 200,705행 |
| 방향 | 종목별 재학습 | 50.57% | [47.97, 53.14] | 미검증 | 16/38 | 1,496행 |
| 방향 | 파운데이션(풀드) | 50.11% | [47.55, 52.73] | 미검증 | 19/38 | 259,893행 |

![파운데이션 대 종목별](results/03_forecast/figures/10_pooled_vs_perstock.png)

**정확도만 보면 종목별이 2.42%p 앞선다.** 표본을 179배로 늘려도 종목 고유의
성질을 이기지 못했다. 예측 가능한 부분이 종목마다 다른 곳에 있다는 뜻이다.

**그런데 파운데이션도 신뢰하한이 50.61%로 50%를 유의미하게 넘는다.** 이게
결론을 바꾼다 — 단독으로 서비스에 쓸 수 있다는 뜻이고, 그러면 **6,228종목
전부**가 대상이 된다.

### 한 번도 배우지 않은 종목도 맞히는가 — 이게 진짜 질문이었다

위 두 줄에는 구멍이 있다. **평가 38종목이 학습 풀 153종목 안에 들어 있다.**
그래서 재고 있던 것은 *시간 일반화*("어제까지 배운 걸로 오늘을 맞히나")이지
*종목 일반화*("한 번도 안 배운 종목을 맞히나")가 아니었다. 6,228종목에
배포하겠다면서 정작 그 주장은 검증하지 않은 상태였다.

그래서 **평가 38종목을 학습에서 통째로 뺐다** (153 → 115종목). 학습 표본이
258,363행에서 200,705행으로 줄고, 모델은 이 38종목을 **단 한 행도 본 적이
없다.** 평가 행은 앞의 둘과 완전히 같은 1,443건이다.

```
학습에 포함된 종목   53.23%  [50.61, 55.77]   26/38
한 번도 배운 적 없음  53.24%  [50.68, 55.78]   25/38
                    ────────
                    차이 +0.01%p
```

**차이가 0.01%p 다.** 성능이 "그 종목을 외웠기 때문"이 아니라 **종목들 사이에
공통된 것을 배웠기 때문**임을 보인다. 재현은 한 줄이다.

```bash
python cli.py eval-pooled --holdout
```

이것이 이 모델을 **파운데이션**이라 부를 수 있는 근거이고, 동시에 아무 종목
코드나 받아도 되는 근거다. 카카오도 알테오젠도 학습에 없었지만 같은 성능이
나온다.

### 그래서 파운데이션을 기본으로 확정했다

| | 파운데이션 (기본) | 종목별 재학습 (`precise=True`) |
|---|---|---|
| 균형정확도 (변동성) | 53.23% · **유의미** | 55.65% · 유의미 |
| 조회 지연 | **167ms** | 7.0초 (42배) |
| 관심종목 20개 | **3.3초** | 140초 |
| 대상 종목 | **6,228종목 전부** | 250봉 이상만 |
| 신규 상장 | **된다** (저신뢰 응답) | 안 된다 |

2.42%p 를 42배의 지연과 맞바꾸는 선택인데, **관심종목 목록에서는 성립하지
않는다.** 20종목에 140초가 걸리는 화면은 만들 수 없다. 게다가 종목별 방식은
250봉 미만 종목을 아예 거절하므로 "아무 종목이나 된다"는 요구를 못 지킨다.

한 종목을 펼쳐 볼 때는 `precise=True` 로 정밀 모드를 켜면 된다. 어느 경로로
답이 나왔는지는 응답의 `방식` 필드에 실려 나간다.

### 피처는 무엇이 기여했나 — 어블레이션

같은 조건에서 피처 묶음만 바꿔 가며 쟀다. 각 칸은 그 묶음의 **최고 모델**이다.

| 피처 묶음 | 변동성 | 50%초과 | 방향 | 50%초과 |
|---|---|---|---|---|
| 기술+시장 | 53.05% | 25/38 | 50.66% | 17/38 |
| +테마 | 53.36% | 24/38 | **51.63%** | **23/38** |
| **+뉴스 (전체)** | **54.22%** | **28/38** | 51.15% | 17/38 |

여기서 한 가지가 선명하게 갈린다.

```
뉴스   변동성 +0.86%p, 종목 24 → 28   방향 -0.48%p, 종목 23 → 17
테마   변동성 +0.31%p, 종목 25 → 24   방향 +0.97%p, 종목 17 → 23
```

**뉴스는 "얼마나 움직일지"는 알려 주지만 "어느 쪽으로"는 알려 주지 않는다.**
기사가 쏟아진 날 주가가 크게 움직이는 건 맞다 — 그런데 그 방향은 이미
가격에 들어가 있다. 방향 쪽에서 뉴스를 얹었더니 50%를 넘는 종목이 오히려
23개에서 17개로 줄었다. 과적합만 쌓였다는 뜻이다.

**테마는 반대다.** 이웃 종목이 어제 어땠는지는 방향에 도움이 되지만
(+0.97%p, 종목 +6) 변동성에는 거의 기여하지 않는다.

전부 켜는 것이 늘 옳지는 않다는 걸 측정이 보여 줬다.

### 급락 후 반등 — 두 번째로 통과한 신호

⚠️ **표본이 독립이 아니라서 두 번 잰다.** 급락은 시장 전체가 같이 빠지는
날에 몰린다. \|z\|>3 신호 875건이 서로 다른 날짜 **561개**에 들어 있고
하루 최대 17종목이 동시에 걸렸다. 그날 시장이 반등하면 17건이 한꺼번에
맞는다 — 독립 관측 17개가 아니라 사실상 1개다. 윌슨 구간은 독립을
가정하므로 그대로 쓰면 유의성이 부풀려진다.

| \|z\| | 단순 집계 순초과 | **날짜 단위 순초과** | 날짜 수 | 판정 |
|---|---|---|---|---|
| 2.0 | +3.85%p | +1.74%p | 1,115 | **유의성 없음** |
| 2.5 | +6.00%p | +3.60%p | 810 | 유의 (아슬) |
| **3.0** | +6.93%p | **+4.94%p** | 561 | 유의 |

**같은 날 신호를 하나로 묶은 오른쪽이 정직한 값이다.** 가장 약한 2.0은
보정 후 유의성을 잃었다 — 그것도 그대로 싣는다.

살아남은 근거 둘:

1. **단조 증가** — 임계값을 올릴수록 효과가 커진다. 우연이라면 임계값과
   무관해야 한다.
2. **사후검증 통과** — 시계열을 앞/뒤로 갈라 따로 재도 양쪽에서 나온다
   (앞 +7.89%p, 뒤 +6.11%p).
3. **비대칭** — 급등 후 하락은 −0.89~−2.08%p로 효과가 없다. 급락에는
   반대매매·손절·마진콜 같은 **가격을 보지 않는 강제 매도**가 섞여 과도하게
   밀리지만, 급등은 자발적 매수라 되돌릴 압력이 약하다. 한쪽에서만 나오는
   효과라는 점이 이 발견의 신뢰도를 스스로 증명한다.

이 발견은 사용자의 관찰에서 나왔다 —
*"이미 다 오른 뒤에 이상 상승 신호가 뜬다. robust z 가 후행이라 그런가?
그렇다면 과하게 빠졌을 때 반등 신호를 주면 맞지 않나?"*

## 측정을 어떻게 하는가

### 미래를 보지 않는다

```
D일 예측
 ├ 학습 데이터  라벨까지 확정된 행만 (t+1 ≤ D-1)
 ├ 입력 피처    D-1 종가 시점
 └ 정답         D일 결과
```

**날짜마다 다시 학습한다.** 한 번 학습해 전 구간을 평가하면 D+3의 정보로
D를 맞히게 되어 정확도가 실제보다 높게 나온다.

장중에 받은 미완성 일봉은 버린다. 실측: 2026-08-18 장중 삼성전자 일봉의
거래량이 1,408만이었는데 직전 사흘은 2,100만~3,553만이었다.

#### 말이 아니라 코드로 확인한다

워크포워드는 **조용히 깨진다.** 인덱싱을 한 칸 잘못 잡거나, 롤링 통계를
자르기 전에 걸거나, 이웃 종목을 전 구간 상관으로 고르면 — 예외는 안 나고
정확도만 올라간다. 틀린 걸 잘한 걸로 착각하게 되는 유일한 방식이다.

```bash
python tests/test_no_lookahead.py
```

```
✅ 평가 첫날 예측 0.5474 · 임계값 0.54 불변
✅ 이웃 수익률 1497행 일치 — 이웃 선택은 앞구간에만 의존
✅ 임계값 0.54 — 결정적이고 범위 안 [0.35, 0.66]
✅ 장 마감 이후 — 버릴 미완성 봉 없음 (봉 1873개)
4/4 통과
```

첫 검사가 핵심이다. **평가일 이후 행을 전부 난수로 덮고** 같은 날 예측이
바뀌는지 본다. 바뀌면 어딘가에서 미래를 읽고 있다는 뜻이다. 누설 경로를
미리 알 필요가 없다는 점이 이 방식의 강점이다 — 피처든 라벨이든
스케일러든, 뒷구간을 건드렸는데 앞이 흔들리면 그것 자체가 증거다.

### 균형정확도를 쓴다 — 50%가 진짜 무작위가 되도록

단순 적중률은 라벨이 쏠리면 부풀려진다. 7일 평가에서 5일이 같은 클래스면
**항상 그것만 찍어도 71%**다. 실제로 그 함정에 빠져 "변동성 57.9%, 유의미"라고
보고했다가 뒤집혔다 — 진짜 기준선이 67.2%였다.

```
균형정확도 = (상승일 적중률 + 하락일 적중률) / 2
```

항상 한쪽만 찍으면 1.0과 0.0의 평균 = 0.5다. **쏠림이 얼마든 무작위는 정확히
0.5**이므로 50%를 기준선으로 두고 비교하는 것이 그대로 정당해진다.
학습에도 `class_weight="balanced"` 를 적용한다.

### 신뢰구간을 항상 같이 낸다

7회 중 6회(85.7%)의 95% 신뢰구간은 약 49~97%로 동전 던지기와 구별되지 않는다.
n이 작을 때 정규근사를 쓰면 구간이 1을 넘거나 뒤집히므로 **윌슨 구간**을 쓴다.

## 평가 대상 — 지수별 규칙 선택

손으로 고르면 "잘 나오는 것만 골랐다"는 말을 듣는다. 규칙으로 뽑고 시드를
고정해 누가 돌려도 같은 종목이 나오게 했다.

| 지수 | 선택 |
|---|---|
| KOSPI · KOSDAQ · NASDAQ · S&P500 | 각 **상위 3 + 중간 3 + 하위 3 + 무작위 1** |

실측: 에스엘에스바이오는 1,969원에 13거래일째 고정이라 평가 7일이 전부
"잔잔함"이었고, **아무 모델이나 100%를 받았다.**

## 뉴스를 어떻게 쓰는가

뉴스는 **기본으로 켜져 있다** (`DEFAULT_FEATURES = "all"`).

### 과거 뉴스를 소급 수집한다

한동안 `when:7d` 만 써서 최근 7일치만 모았다. 학습 구간은 6년인데 뉴스가
9일치뿐이었으니, 그 열은 **사실상 상수**였다 — "뉴스를 쓴다"고 적어 놓고
실제로는 아무것도 안 쓰는 상태였다.

구글 뉴스 RSS 는 `after:` / `before:` 를 받는다. 구간을 12일씩 쪼개
걸어 내려가면 과거도 모인다.

```bash
python cli.py backfill-news --days 365   # 한 번만
python cli.py collect-news               # 그 뒤로는 매일 오늘치만
```

| | 소급 수집 전 | 후 |
|---|---|---|
| 아카이브 | 9,979건 · **9일** | 38,865건 · **365일** |
| 삼성전자 평가 구간 뉴스 | 0.3% | **75.0%** |
| SK하이닉스 평가 구간 뉴스 | 0.3% | **72.5%** |
| NVIDIA 평가 구간 뉴스 | 40% | **100%** |

### 같은 단어를 같은 척도로 — `lexicon_ko.py`

교차언어 전이 모델(`newsxfer.py`)은 xforecast 미국 뉴스 47만 건을
**사전 방식**으로 채점한 피처로 학습했다. 그런데 국내 뉴스는 KR-FinBert 로
채점해 넣고 있었다.

```
학습:  영문 뉴스 → LM 사전     → polarity, 평활항 SMOOTH=3  (근거 1개면 ±0.25)
적용:  국내 뉴스 → KR-FinBert  → softmax 확률                (확신하면 0.99)
```

**같은 이름의 열에 서로 다른 척도의 값이 들어갔다.** 미국에서 배운 임계값이
한국에 맞을 리가 없다.

그래서 영문 사전의 어휘를 **국내 표현으로 대응**시킨 사전을 만들었다.
사전적 번역이 아니라 같은 사건을 가리키는 표현으로 맞춘다.

| 영문 | 국문 대응 |
|---|---|
| beat / surpass | 상회 · 웃돌 · 어닝서프라이즈 |
| miss / shortfall | 하회 · 밑돌 · 어닝쇼크 |
| upgrade | 목표주가 상향 · 투자의견 상향 |
| guidance cut | 가이던스 하향 · 전망 하향 |

긍정 57 · 부정 68 · 불확실 19개. 한국어는 교착어라 어미가 붙으므로
("상승했다/상승세/상승폭") 토큰 일치가 아니라 **부분 문자열**로 세고,
부정어는 영어와 반대로 뒤에 오므로("회복 못 했다") 뒤쪽 12글자를 본다.

```
+0.500  삼성전자, 3분기 영업이익 시장 기대치 상회…목표주가 상향
-0.571  SK하이닉스 급락, 실적 부진 우려에 외국인 매도
-0.250  테슬라 주가 회복 못 했다          ← 부정 처리
```

이제 전이 피처는 **양쪽 다 사전으로** 채점한다. 학습 분포와 적용 분포가
맞는다. KR-FinBert 는 지우지 않았다 — 사용자에게 읽어 줄 문장 톤에는
그쪽이 낫고, 용도가 다르다.

```
전이 피처   KR·US 모두 사전 (lexicon_ko / lexicon)  ← 척도를 맞춰야 하므로
읽어 줄 톤  KR-FinBert-SC / ProsusAI-finbert        ← 문장 품질이 중요하므로
```

**언어는 섞지 않는다.** 로케일이 `hl=ko&gl=KR` 로 고정돼 있어 "Tesla stock"
질의에 한국어 기사가 섞여 온 적이 있다. 시장마다 자기 로케일로 받는다.

### 남은 결측은 중립 0.5

NaN 으로 두면 모델이 "값이 있는 행 = 최근 며칠"을 외워 확률이 0%/100%로
포화한다(실측). 0.5 로 채우면 열이 100% 차서 그 누수가 구조적으로
불가능해지고, "뉴스 없음 = 중립"이라는 뜻도 정확히 표현된다.

커버리지는 종목마다 다르다. `results/03_forecast/data/news_coverage.csv` 에
전 종목 수치를 그대로 싣는다 — 평균만 적으면 편차가 사라진다.

## 차트 유사도 — "닮았다"를 어떻게 재는가

### 가격 상관만 쓰면 안 된다

처음엔 z-정규화한 **종가 경로의 상관** 하나로 순위를 매겼다. 그랬더니
유사도 0.97 짜리 매치의 두 곡선이 **눈으로 봐도 달랐다.**

이유는 간단하다. **추세가 상관을 지배한다.** 120일 동안 둘 다 우상향한
구간이면 봉마다의 움직임이 전혀 달라도 상관이 0.95를 넘는다.

거리를 더 넣어 봐야 소용없다는 것도 계산으로 나온다. z-정규화된 두 벡터는

```
‖a − b‖² = 2n(1 − r)
```

이라 **유클리드 거리가 상관의 단조 함수**다. 새 정보가 0이다.

### ⚠️ 그런데 이 진단이 틀렸다 — 되돌린 기록

원인을 저렇게 짚고 **일간 수익률 상관을 주축(0.45)** 으로 올려 재순위를
넣었다. 그런데 진짜 원인은 따로 있었다 (바로 아래 절). 형태상관은 처음부터
멀쩡했고, 그 위에 얹은 재순위가 오히려 **눈에 보이는 순서를 망가뜨렸다.**

실측으로 잡혔다.

| NVDA 질의 매치 | 형태상관 | 수익률상관 | 종합 | 순위 |
|---|---|---|---|---|
| Extra Space Storage | **0.884** (최고) | 0.214 | 0.569 | **5위** |
| Take-Two | **0.739** (최저) | 0.407 | 0.575 | **1위** |

**가장 닮아 보이는 것이 꼴찌, 가장 안 닮은 것이 1등**이 됐다. 25개 사례
전체에서 종합점수와 형태상관의 상관은 0.556, 수익률상관과는 0.926이었다 —
이름은 유사도인데 실제로 재는 것은 **동조도**였다.

시장 간 비교도 깨졌다. 국내 매치는 같은 기간이라 시장 베타를 공유해 동조가
높고(0.85~0.87), 미국 매치는 다른 시기라 낮다(0.57~0.63). 같은 0.7이 시장에
따라 다른 뜻이 됐다.

### 최종 — 형태가 순위를 정한다

| 성분 | 가중 | 재는 것 |
|---|---|---|
| **형태상관** | **0.70** | **눈에 보이는 닮음. 이게 순위를 정한다** |
| 진폭일치 | 0.20 | 하루 0.5% 움직인 구간과 5% 구간을 구분 |
| 수익률상관 | 0.10 | 같은 모양이면 실제로 함께 움직인 쪽을 앞에 |

`추세일치`는 순위에서 뺐다. 그림을 z-정규화해서 그리므로 총변화율 차이는
**이미 지워진 뒤**라 눈에 보이지도 않는다 (종합과의 상관 0.039 — 잡음이었다).
값은 계속 계산해서 `components`로 실어 보낸다.

2단계로 돈다 — ① 형태 주도로 상위 300개 회수(행렬곱 2회) ② 세 성분으로
재순위. 검색은 여전히 밀리초다.

되돌린 뒤 측정:

| | 종합 ↔ 형태상관 | 종합 ↔ 수익률상관 | 국내 점수 | 미국 점수 |
|---|---|---|---|---|
| 수익률 주도 (폐기) | 0.556 | 0.926 | 0.85~0.87 | 0.57~0.63 |
| **형태 주도 (채택)** | **0.909** | 0.587 | 0.77~0.95 | 0.82~0.87 |

순위가 눈에 보이는 것을 따라가고, **시장이 달라도 같은 척도**가 됐다.

응답에는 `유사도`(모양)와 `동조도`(수익률상관)를 **따로** 싣는다. 둘은 다른
질문이고, 모양이 0.98로 닮았는데 동조가 0.21인 짝이 흔하다.

### ⚠️ 그림이 다른 구간을 그리고 있었다

숫자를 고치기 전에 **그림 쪽 버그가 따로 있었다.** 매칭은 질의를 20봉 물려
`[-140:-20]` 구간으로 하는데, 그림은 `close[-W:]` 즉 `[-120:]` 을 그렸다.
**20봉 어긋난 채로 겹쳐 그린 것**이다.

증상이 고약했다 — 유사도 0.98 이라고 적힌 패널에서 두 곡선이 눈에 띄게
어긋나 보였다. 숫자는 맞고 그림만 틀린 경우라 엉뚱한 곳을 오래 뒤졌다.
지금은 검색이 실제로 쓴 배열(`query.segment`)을 **그대로** 그린다.

## 이상감지 — 확실히 작동하는 부분

핵심 문제는 정확도가 아니라 **알림 폭주**였다. 고정 임계값 |z|>3은
종목당 하루 9.8건을 냈다 — 아무도 못 듣는다.

| | 일평균 알림 | 정밀도 | 리프트 |
|---|---|---|---|
| 고정 \|z\|>3 | 7.68 | 0.022 | 4.0× |
| + 채널 병합·쿨다운 | 3.78 | 0.032 | 6.1× |
| + 예산 임계값 | 0.52 | 0.065 | 12.2× |
| **+ 절대 크기 게이트 (채택)** | **0.49** | **0.068** | **12.9×** |
| 증권사식 고정 ±2%/30분 | 4.43 | 0.010 | 1.7× |

학습 랭커는 홀드아웃 49종목(평가 60,372행)에서 규칙 기준선 대비
**PR-AUC 3.0배** (0.1078 vs 0.0357), ROC-AUC 0.8433
— `01_anomaly/validation/08_training_report.json`.

> ⚠️ 아래 TabPFN 표의 **2.35배**(0.249 vs 0.1058)와 헷갈리기 쉽다. 둘은
> **다른 실험**이다 — 이쪽은 종목 홀드아웃 49종목이고, 저쪽은 무작위 20,000행
> 표본에 기준선 정의도 다르다. 같은 숫자를 재는 것이 아니다.

### 위험도 — "지금 들어가기 얼마나 어려운가"

변동성·이상빈도·갭·꼬리·유동성 다섯 축을 **비교군 안에서의 백분위**로
환산해 가중 평균한다. 절대 기준을 안 쓰는 이유는 시장 국면마다
"높은 변동성"의 값이 달라지기 때문이다.

위험도가 높다고 떨어진다는 뜻이 **아니다.** 변동 폭과 진입·청산 난이도만 말한다.

## 파운데이션 모델 (TabPFN)

이상감지 랭커에서 GBM과 정면 비교했다. TabPFN은 CPU 상한이 1000행이라
**GBM도 같은 1000행으로** 한 번 더 세웠다 — 없으면 "TabPFN이 나쁜 것"과
"표본이 적어서 나쁜 것"을 구별할 수 없다.

| 모델 | 학습 표본 | PR-AUC | ROC-AUC |
|---|---|---|---|
| GBM | 109,500 | 0.2490 | 0.8424 |
| **TabPFN** | **1,000** | **0.1992** | **0.8170** |
| GBM | 1,000 | 0.1822 | 0.7793 |
| 규칙 기준선 | — | 0.1058 | 0.6767 |

**같은 1000행에서 TabPFN이 GBM을 이긴다(+0.0170).** 표본 100분의 1로 전체
GBM의 80%에 도달했다. 추론이 행당 약 11ms라 관심종목 10개면 0.1초,
대량 평가엔 안 맞는다.

## 알려진 한계

- **국내 뉴스 아카이브가 1년치뿐이다.** 소급 수집으로 평가 구간은 덮었지만
  (평가 구간 커버리지 KR 62.5% · US 73.6%), 학습 구간 전체로는 KR 8.2% ·
  US 21.3%에 그친다. 앞쪽 몇 년은 여전히 비어 있다.
  구간당 100건 상한이 있어 거래가 뜸한 소형주는 커버리지가 낮다
  (Solowin 7%, 피코그램 12%). 종목별 수치는 `news_coverage.csv` 에 그대로 싣는다.
- **7일 평가는 시연용이다.** 판단은 40일 측정과 신뢰구간으로 해야 한다.
- 검증 표본이 시장 국면 하나만 담는다. 종목 일반화는 확인했지만
  기간 일반화는 확인하지 못했다.
- 급락 반등 52.5%는 **47.5%는 더 빠진다**는 뜻이다. 거래비용을 넣으면
  남는 게 없을 수 있다. 매매 신호가 아니라 상황 전달용이다.
- **검증 구간이 시장 국면 하나뿐이다.** 40거래일은 2026년 여름 한 구간이고,
  급락 반등의 사후검증도 같은 6년 안에서 앞/뒤를 가른 것이다. 다른 국면
  (2008·2020 같은 급락장)에서도 같은지는 확인하지 못했다.
- 등락률 회귀는 MAE 4.66%p로 **"항상 0%"(4.43%p)보다 나쁘다.** 값은
  표시하되 그 사실을 함께 싣는다.
- 3단 딥러닝 탐지기는 +1.3%에 817ms — 껐지만 지우지 않았다.
- ONNX는 속도 이득이 없다(822ms vs 866ms). 가치는 Java 이식성이다.
