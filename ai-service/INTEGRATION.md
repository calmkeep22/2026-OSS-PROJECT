# 연동 가이드 — 트레이딩 툴에 AI 붙이기

이 문서는 **백엔드를 붙이는 사람**을 위한 것이다. AI 내부 구조는 몰라도 되고,
아래 함수 세 개와 응답 스키마만 알면 된다.

```python
from accessible_investor import serving as SV

SV.brief("005930",   bars=df)    # ★ 셋을 합친 한 줄 요약 (관심종목용)

SV.predict("005930", bars=df)    # 다음 거래일 예측
SV.anomaly("005930", bars=df)    # 이상 움직임 + 위험도
SV.similar("005930", bars=df)    # 닮은 차트 종목
```

전부 **코스피·코스닥·나스닥·S&P500 전 종목(6,228개)** 을 받는다.
관심종목에 담을 수 있는 것이면 다 된다.

**대부분의 화면은 `brief()` 하나면 된다.** 셋을 따로 부르고 백엔드에서
합치면 합치는 방식이 화면마다 달라진다 — 어느 걸 먼저 읽을지, 하나가
실패하면 전체를 실패로 볼지, 문장을 어떻게 이을지가 전부 재량이 된다.
`brief()` 는 그 결정을 한 곳에 박아 두고, **부분 실패를 전체 실패로 만들지
않는다** (유사도가 안 돼도 예측·이상감지는 돌려준다).

```python
r = SV.brief("196170", bars=df, with_similar=True)
print(r["문안"])
# 알테오젠이 2026-08-20에 약한 신호 수준으로 상승했습니다. 등락률 10.87퍼센트로,
# 최근 움직임 대비 2.42배 수준입니다. 이 종목의 위험도는 높음입니다.
# 다음 거래일(08월 21일) 크게 움직일 확률 52퍼센트, 잔잔할 확률 48퍼센트로 봅니다.
# … 최근 흐름은 SK바이오팜과 가장 닮았습니다 (유사도 77퍼센트).

r["예측"]      # predict() 응답 전체 (실패 시 None)
r["이상감지"]   # anomaly() 응답 전체 (실패 시 None)
r["유사종목"]   # 상위 3개 요약 (with_similar=True 일 때만)
r["오류"]      # {"유사도": "ReferenceMissing: …"} 처럼 실패한 것만
```

`with_similar` 는 기본이 꺼짐이다 — 목록 화면에 쓸 정보가 아니고, 인덱스를
처음 만들 때 몇 초가 든다. 종목 상세에서만 켜면 된다.

### HTTP 로 감싸기 — 최소 예시

```python
from fastapi import FastAPI, HTTPException
from accessible_investor import serving as SV

app = FastAPI()

@app.on_event("startup")
def _warm():
    SV.warm()                      # 첫 사용자가 로딩 비용을 뒤집어쓰지 않게

@app.get("/api/stock/{code}")
def stock(code: str, detail: bool = False):
    try:
        bars = kiwoom.daily_chart(code)          # 팀원 쪽 함수
        return SV.brief(code, bars=bars, with_similar=detail)
    except SV.UnknownSymbol:
        raise HTTPException(404, "그런 종목이 없습니다")
    except SV.InsufficientData as e:
        raise HTTPException(422, f"자료 부족 ({e.have}봉)")
    except SV.ServiceError as e:
        raise HTTPException(400, str(e))
```

이게 사실상 전부다. 나머지는 UI 쪽 일이다.

## 1. 30초 요약

| | 내용 |
|---|---|
| 입력 | 종목코드(또는 종목명) + 일봉 OHLCV |
| 봉 공급 | **키움에서 받은 봉을 그대로 넘기면 된다.** 안 넘기면 자체 조회 |
| 학습 | **조회 시점에 학습하지 않는다.** 저장된 모델을 불러 확률만 계산 |
| 지연 | 예측 **167ms** · 이상감지 **15ms** · 유사도 **14ms** (봉을 넘겼을 때, 워밍업 후) |
| 신규상장 | **된다.** 데이터가 짧으면 거절 대신 `신뢰도`를 낮춰 응답 |
| 네트워크 | `bars` 를 넘기고 `with_news=False` 면 **요청 0건** |
| 스레드 | 읽기 전용이라 안전. 프로세스당 `warm()` 한 번 |

### 관심종목 목록에서 뉴스를 켜지 말 것

뉴스는 **기사를 받아 오느라 종목당 1.4초쯤** 더 든다. 계산이 아니라 대기다.
10종목을 실측하면 이렇게 갈린다.

| 호출 방식 | 종목당 | 관심종목 30개 |
|---|---|---|
| `brief(코드)` — 뉴스 켬 | 1,549ms | **46초** |
| `brief(코드, with_news=False)` | 366ms | 11초 |
| `brief(코드, bars=키움봉, with_news=False)` | **188ms** | **5.6초** |

목록 화면은 세 번째 줄로 그리고, **뉴스는 사용자가 한 종목을 펼쳤을 때만**
켜는 것이 맞다. 목록에서 켜면 화면이 멈춘 것처럼 보인다.

뉴스를 못 받아도 예측은 나온다 — 뉴스 피처 4개가 결측이 되고 응답의
`뉴스반영일수` 가 `0` 으로 실려 나갈 뿐이다. 실제로 **네트워크를 완전히
끊고도** 예측·이상감지·유사도 세 기능이 모두 응답하는 것을 확인했다
(봉을 넘겼을 때).

## 3. 봉 데이터 형식

`bars` 는 pandas DataFrame 이다. **열 이름과 날짜 표기는 관대하게 받는다.**

```python
# 이 셋은 전부 동일하게 처리된다
df1 = pd.DataFrame({"open":…, "high":…, "low":…, "close":…, "volume":…},
                   index=pd.DatetimeIndex([...]))
df2 = pd.DataFrame({"시가":…, "고가":…, "저가":…, "종가":…, "거래량":…,
                    "일자": ["20260818", "20260819", …]})
df3 = pd.DataFrame({"Open":…, …, "Date": [...]})
```

- 날짜: 인덱스이거나 `date` / `Date` / `일자` / `날짜` / `체결시간` / `datetime` 열
- 정렬: 안 해도 된다 (내부에서 오름차순 정렬 + 중복 제거)
- 거래량 없으면 0 으로 채운다 (위험도의 유동성 축만 못 쓴다)
- 타임존 붙어 있어도 된다 (떼어 낸다)

### 최소 봉 수

| 봉 수 | 동작 |
|---|---|
| 250개 이상 | `신뢰도="높음"` — 전 피처 사용 |
| 120~249 | `신뢰도="보통"` — 1년 드리프트 피처 없음 |
| 60~119 | `신뢰도="낮음"` |
| 30~59 | `신뢰도="매우낮음"` |
| 30개 미만 | `InsufficientData` 예외 |

> **UI 권고:** `신뢰도` 가 `"낮음"` 이하이면 예측 옆에 그 사실을 반드시 표시할 것.
> 응답의 `문안` 필드에는 이미 그 문장이 들어 있다.

### ⚠️ 미완성 봉을 넣지 말 것

장중에 받은 오늘 일봉은 **종가가 아니라 현재가**다. 그대로 넣으면 "내일을
맞힌다"가 "이미 본 값을 되읽는다"가 된다. 자체 조회 경로는 마감 20분 뒤까지
오늘 봉을 버리지만, **넘겨받은 봉은 그대로 믿는다.** 마감 전이라면 마지막
봉을 빼고 넘기는 쪽이 안전하다.

## 4. `predict()` — 다음 거래일 예측

```python
SV.predict(code, bars=None, *, target="변동성", with_news=True) -> dict
```

```python
SV.predict(code, bars=None, *, target="변동성",
           with_news=True, precise=False) -> dict
```

| 인자 | 기본 | 설명 |
|---|---|---|
| `code` | — | `"005930"` · `"카카오"` · `"NVDA"` · `"Apple"` 다 된다 |
| `bars` | `None` | 키움 봉. 없으면 자체 조회 |
| `target` | `"변동성"` | `"변동성"` 또는 `"방향"` |
| `with_news` | `True` | `False` 면 뉴스 없이 (네트워크 0건, 더 빠름) |
| `precise` | `False` | `True` 면 이 종목으로 새로 학습 (7초, +2.42%p) — 8절 참조 |

### 기본 타깃은 "변동성"이다

변동성(내일 크게 움직일까)이 주력이다. 확신도 상위 30% 구간에서 적중률
**60.83%** (신뢰하한 56.24%) 로, 알림을 걸 만한 것만 골랐을 때의 성능이다.

`target="방향"` 으로 부르면 상승·하락 확률을 받는다. 응답에 실리는
`유의미` 플래그는 **시장별로** 판정한 값이니 UI 에서 그대로 쓰면 된다.
`유의미근거` 에 어느 표본으로 판정했는지 적힌다.

타깃이 `"변동성"` 이면 확률 필드 이름이 `크게움직임확률` / `잔잔함확률` 로 바뀐다.
UI 가 라벨을 직접 만들 필요가 없도록 타깃에 맞춰 내보낸다.

### 「오늘」인가 「내일」인가 — `금일여부`

모델은 언제나 **마지막 확정 봉의 다음 거래일**을 맞힌다. 그게 오늘일 수도
있고 내일일 수도 있다.

| 조회 시점 | 마지막 확정 봉 | `대상일` | `시점` |
|---|---|---|---|
| 장중 (마감 전) | 어제 | **오늘** | `"금일"` |
| 마감 20분 뒤 이후 | 오늘 | 내일 | `"다음 거래일"` |

툴에서는 이게 곧 매매 시점이라 모호하면 안 된다. `문안` 에도 "오늘" /
"다음 거래일(08월 21일)" 로 명시돼 있다.

> ⚠️ `대상일` 은 **다음 영업일**로 계산한다. 공휴일이 끼면 실제 거래일보다
> 앞선 날짜가 나온다. 정확한 캘린더는 미래 날짜라 시세로 알 수 없다.
> 날짜보다 `금일여부` 를 믿는 편이 안전하다.

### ⚠️ `원확률` 을 0.5 와 비교하지 말 것

`임계값` 이 0.5 가 아니다. 라벨 쏠림을 보정하려고 학습 구간에서 따로 고른
값이라 종목·타깃에 따라 0.47 이나 0.49 다. 그래서 **원확률 0.4929 인데 판정은
"크게움직임"** 인 상황이 생긴다.

그 혼란을 없애려고 `상승확률` / `하락확률` 은 **임계값을 50%로 옮긴 뒤** 계산한
값이다. 구간별 선형 단조 변환이라 순서가 바뀌지 않고, **판정과 숫자가 항상
같은 쪽**을 가리킨다.

```
원확률   0 ────────── 임계값 ────────── 1
상승확률 0 ──────────  50%  ────────── 1
```

**UI 는 `상승확률`/`하락확률` 만 쓰면 된다.** `원확률`·`임계값` 은 감사·디버깅용.

## 5. `anomaly()` — 이상 움직임 + 위험도

```python
SV.anomaly(code, bars=None, *, window=60, lookback=60) -> dict
```

**봉 주기를 가리지 않는다.** 5분봉을 넣으면 5분봉 기준 이상치가 나온다.
일봉으로 학습된 예측과 달리 이쪽은 통계 계산이라 주기 종속성이 없다.

```json
{
```

### robust z 가 뭔가

`(오늘 수익률 − 최근 60봉 중앙값) ÷ (MAD ÷ 0.6745)`

보통의 z-score(평균·표준편차)를 안 쓰는 이유는 **이상치가 자기 기준을
오염시키기** 때문이다. 큰 움직임 하나가 표준편차를 키워 스스로를 정상으로
만든다. 중앙값과 MAD 는 그 영향을 받지 않는다. 실측에서 robust z 가 일반 z
보다 **2.8배 많은 이상일**을 잡았다 (47일 대 17일).

### 등급과 **알림 빈도** — UI 설계에 필요한 숫자

240종목 × 최근 250거래일 실측이다. 알림을 어느 등급부터 띄울지 이 표로 정하면 된다.

| \|z\| | 등급 | 국내 발생률 | 미국 발생률 | 관심종목 20개 기준 |
|---|---|---|---|---|
| ≥ 2.0 | 약한 신호 (`이상=true` 의 하한) | 12.3% | 9.9% | 하루 **2~2.5건** |
| ≥ 2.5 | 주목 | 7.4% | 5.2% | 하루 1~1.5건 |
| ≥ 3.0 | 이례적 | 4.6% | 2.9% | 이틀에 1건 |
| ≥ 4.0 | 매우 이례적 | — | — | 드묾 |

정규분포라면 \|z\|>2 는 4.6% 여야 하는데 실제로는 그 2~3배다. 주가 수익률의
꼬리가 두껍기 때문이고, **이 숫자 자체가 정상**이다.

> **권고:** 푸시 알림은 `등급 in ("이례적", "매우 이례적")` 부터.
> `약한 신호` 까지 밀어 넣으면 관심종목 20개에서 하루 2건 넘게 울려 금방 꺼진다.
> 목록 화면의 배지 정도로 쓰는 편이 낫다.

### ⚠️ 조용한 종목과 시끄러운 종목의 기준이 다르다

robust z 는 **그 종목 자기 과거** 기준이다. 하루 5%씩 움직이는 종목의 −7.8%
는 `z=−1.2` 로 정상이고, 하루 0.5% 움직이는 종목의 −2% 는 `z=−3.5` 로
이례적이다. 이게 의도한 동작이다 — 절대 등락률로 자르면 변동성 큰 종목만
알림을 독점한다. UI 에서 "등락률이 큰데 왜 정상이냐"는 문의가 오면 이 설명이다.
응답의 `평소변동폭`(predict) 과 `위험도.축별백분위.변동성` 이 그 근거다.

### 위험도는 왜 비교군이 필요한가

"이 종목은 변동성 0.42" 는 사용자에게 아무 뜻이 없다. "300종목 중 상위 19%"
라야 뜻이 있다. 비교군 300종목의 분포를 **미리 계산해 파일로 저장**해 두었기
때문에 조회 시점에는 다른 종목 시세를 한 건도 받지 않는다.

`위험도` 가 빈 `{}` 로 오면 기준분포 파일이 없는 것이다 (`serve health` 확인).

## 6. `similar()` — 닮은 차트 종목

```python
SV.similar(code, bars=None, *, window=120, top_k=5, forward=20) -> dict
```

후보 풀은 비교군 패널(시장별 300~500종목 × 6년)에서 종목당 200구간씩 뽑은
약 6만 구간이다. 검색은 z-정규화 후 행렬곱 한 번이라 밀리초다.

### `유사도` 와 `동조도` 는 다른 질문이다

| 필드 | 뜻 | 무엇에 쓰나 |
|---|---|---|
| `similarity` | **모양이 얼마나 닮았나** (형태 0.70 · 진폭 0.20 · 수익률 0.10) | 순위·표시 |
| `동조도` | **봉마다 실제로 함께 움직였나** (일간 수익률 상관) | 페어·헤지 판단 |

모양이 0.98로 닮았는데 동조가 0.21인 짝이 흔하다 — 다른 시기의 다른 종목이
우연히 같은 곡선을 그린 경우다. **UI 는 `similarity` 를 "유사도"로 보여 주고,
`동조도` 는 별도 배지로 두는 편이 오해가 없다.**

점수 범위는 국내 0.77~0.95 · 미국 0.82~0.87 로 **시장이 달라도 같은 척도**다.

```json
{
  "종목코드": "005930", "종목명": "삼성전자", "후보종목수": 299,
  "query": {"code": "005930", "name": "삼성전자",
            "offset": 20, "segment": [...], "forward_path": [...]},
  "results": [
    {"rank": 1, "code": "000660", "name": "SK하이닉스",
     "end": "2024-03-15",
     "similarity": 0.932,          // 모양이 얼마나 닮았나 (형태 주도)
     "동조도": 0.850,               // 봉마다 실제로 함께 움직였나
     "components": {"형태상관": 0.974, "수익률상관": 0.850,
                    "진폭일치": 0.828, "추세일치": 0.055},
     "explain": "…", "segment": [...], "forward_path": [...]}
  ],
  "forward": {"bars": 20, "상승": 3, "하락": 2},
  "disclaimer": "…"
}
```

### 이후 구간을 함께 준다

"닮은 구간 다음에 무슨 일이 있었나"를 상승 몇 건 / 하락 몇 건으로 센다.
`disclaimer` 필드를 UI 에 함께 띄우면 된다.

`query` 에도 `forward_path` 가 있다 — 질의 구간을 `forward` 봉만큼 과거로
물려서 **질의 쪽의 "이후 20일"도 그릴 수 있게** 했다. 안 그러면 매치만 이후
구간이 있어 비교가 되지 않는다.

## 7. 오류 처리

```python
from accessible_investor.serving import (ServiceError, InsufficientData,
                                         UnknownSymbol)

try:
    r = SV.predict(code, bars=df)
except UnknownSymbol:
    return 404, "그런 종목이 없습니다"
except InsufficientData as e:
    return 422, f"자료 부족 ({e.have}봉, 최소 {e.need}봉)"
except ServiceError as e:
    return 400, str(e)
except Exception:
    return 500, "내부 오류"
```

| 예외 | 언제 | 권장 HTTP |
|---|---|---|
| `UnknownSymbol` | 레지스트리에 없는 코드 | 404 |
| `InsufficientData` | 봉 30개 미만 (유사도는 `window+forward` 미만) | 422 |
| `FetchFailed` | 시세 조회 실패 (`bars` 를 안 넘겼을 때만) | 502 |
| `ReferenceMissing` | 비교군 패널 없음 (`similar` 만) | 503 |
| `FileNotFoundError` | 예측 모델 파일 누락 | 503 (기동 실패) |

`UnknownSymbol` 을 뺀 셋은 전부 `ServiceError` 하위라 하나로 잡힌다.
**`bars` 를 넘기면 `FetchFailed` 는 아예 발생하지 않는다** — 조회를 안 하니까.

### 스트레스 검사 결과 (깨지기 쉬운 종목 22개 × 3기능)

| 묶음 | 결과 |
|---|---|
| 신규 상장 1년 내 | 봉이 30개 넘으면 저신뢰로 응답, 미만은 `InsufficientData` |
| 상장 1~3년 | 전부 정상 (402~645봉, 신뢰도 높음) |
| 국내 시총 최하위 | 전부 정상 |
| 비교군 패널 밖 종목 | 전부 정상 (이웃은 섹터로 폴백) |
| 이중 클래스주 (BRKB·BFB) | 전부 정상 |

**66건 중 성공 61 · 정상거절 5 · 예상 못 한 실패 0.**
정상거절 5건은 봉이 47~60개뿐인 최근 분할 상장주의 `similar` 요청으로,
비교 구간 140봉을 못 채운 정당한 거절이다.

`UnknownSymbol` 은 `KeyError` 의 하위 클래스이지만 `ServiceError` 는 아니다.
셋 다 잡으려면 위 예시처럼 따로 적어야 한다.

## 8. 성능과 배치

### 프로세스 기동 시 한 번

```python
SV.warm()      # 약 10초. 이걸 부르면 이후 모든 요청이 균일하다.
```

**반드시 부를 것.** 안 부르면 첫 사용자가 그 비용을 혼자 뒤집어쓴다.

`warm()` 이 하는 일과 실측:

| | 내용 |
|---|---|
| 예측 모델 2개 | 파일에서 적재 |
| 비교군 패널 2개 | 파일에서 적재 |
| **지수 4개** | **네트워크에서 받는다** (KOSPI 1.7초 · NASDAQ 2.3초) |
| 종목 레지스트리 | 파일에서 적재 |
| 예열 예측 | 버리는 예측 한 번 — sklearn·BLAS 초기화를 흡수 |

```
warm() 안 부름 → 첫 predict 4,519ms → 이후 150ms
warm() 부름    → 첫 predict   150ms
```

> ⚠️ **지수만은 저장소에 없다.** 시장맥락 피처 8개(지수 수익률·베타·상관
> 등)가 이걸 쓴다. 못 받아도 예측은 답을 내지만 **32개 중 8개가 조용히
> 결측**이 된다. `health()` 가 `"지수"` 항목으로 그 상태를 보고하므로
> 기동 점검에서 `전체정상: true` 를 확인할 것. 받은 뒤에는 디스크에
> 캐시되어 장 마감 전까지 재사용된다.

### 실측 지연 — 8종목 × 3회 중앙값 (봉 외부공급, 워밍업 후)

| 호출 | 지연 | 내역 |
|---|---|---|
| `predict(with_news=False)` | **167ms** | 피처 32개 계산 150ms + 앙상블 추론 17ms |
| `predict(with_news=True)` | 1~3초 | 뉴스 RSS 요청이 거의 전부 |
| `predict(precise=True)` | **7.0초** | 이 종목으로 앙상블 3모델 + 임계값 재적합 |
| `anomaly` | **15ms** | 롤링 통계뿐 |
| `similar` | **14ms** | 행렬곱 1회 (인덱스 재사용) |

느린 구간은 둘뿐이다 — **뉴스 요청**과 **정밀 모드**. 둘 다 끄는 것이 기본값이다.

### 학습에 없는 종목도 같은 성능이 나오나

**나온다.** 이게 아무 종목 코드나 받아도 되는 근거다.

평가 38종목을 학습에서 통째로 빼고(153 → 115종목) 같은 1,443건을 다시 쟀다.

| | 균형정확도 | 95% 신뢰구간 | 50%초과 |
|---|---|---|---|
| 학습에 포함된 종목 | 53.23% | [50.61, 55.77] | 26/38 |
| **한 번도 배운 적 없는 종목** | **53.24%** | [50.68, 55.78] | 25/38 |

**차이 +0.01%p.** 성능이 그 종목을 외웠기 때문이 아니라 종목들 사이에
공통된 것을 배웠기 때문임을 뜻한다. 카카오도 알테오젠도 학습 풀에 없지만
같은 성능이 나온다.

재현: `python cli.py eval-pooled --holdout`

### `precise=True` — 언제 켜나

```python
SV.predict(code, bars=df)                  # 167ms · 균형정확도 53.23%
SV.predict(code, bars=df, precise=True)    # 7.0초 · 균형정확도 55.65%
```

**2.42%p 를 42배의 지연과 맞바꾸는 선택이다.** 같은 38종목 × 40거래일에서
잰 값이고, 둘 다 50%를 유의미하게 넘는다.

| 화면 | 권장 | 이유 |
|---|---|---|
| 관심종목 목록 | 기본 (167ms) | 20종목 = 3.3초. 정밀이면 140초가 되어 성립하지 않는다 |
| 종목 상세 | `precise=True` | 사용자가 한 종목을 보는 중이라 7초를 기다릴 맥락이 있다 |
| 푸시 알림 배치 | 기본 | 종목 수가 많다 |

표본이 250행에 못 미치면 **조용히 파운데이션으로 되돌린다.** 응답의 `방식`
필드로 확인할 것 — `"종목별학습"` / `"파운데이션"` / `"파운데이션(표본부족)"`.

### 관심종목 일괄 처리

```python
SV.warm()
rows = []
for code in watchlist:
    try:
        rows.append(SV.predict(code, bars=kiwoom_bars[code], with_news=False))
    except SV.ServiceError as e:
        rows.append({"종목코드": code, "오류": str(e)})
```

20종목이면 **3.3초**. 병렬화가 필요 없다.

### 스레드 안전성

적재된 모델과 패널은 **읽기 전용**이라 여러 스레드가 동시에 불러도 된다.
다만 첫 적재는 락이 없으므로 `warm()` 을 기동 시점에 **한 번** 부를 것.

## 9. 운영 — 무엇을 언제 다시 돌리나

| 주기 | 명령 | 이유 |
|---|---|---|
| 매일 (장 마감 후) | `python cli.py collect-news` | 뉴스 아카이브 적립 |
| 월 1회 | `python cli.py registry --refresh` | 신규 상장·상장 폐지 반영 |
| 분기 1회 | `python cli.py reference --build` | 비교군 시세·위험도 기준분포 갱신 |

모델을 매일 재학습할 필요는 없다. 예측 입력(피처)은 매일 새로 계산되므로,
모델 자체는 시장 구조가 바뀔 때만 갱신하면 된다.

> **뉴스 수집을 거르면 조용히 나빠진다.**
> 아카이브가 멈추면 뉴스 피처가 중립 0.5 로 채워지면서, 예외 없이 예측만
> 조금씩 무뎌진다. 매일 실행되게 걸어 둘 것.

## 10. 사용자에게 반드시 보여야 하는 것

법적 문제이자 접근성 문제다. 이 도구의 사용자는 화면을 보기 어려운 사람이라
**숫자만 읽어 주면 판단 근거를 스스로 확인할 수 없다.**

1. **`문안` 필드를 그대로 읽어 줄 것.** 스크린리더용으로 쓴 문장이다.
   숫자를 앞에 두지 않고, 신뢰도가 낮으면 그 사실이 문장 안에 들어 있다.
2. **`유의미: false` 인 예측(방향)은 그 사실을 함께 말할 것.**
3. **`신뢰도` 가 "낮음" 이하면 표시할 것.**
4. **`similar` 의 `disclaimer` 를 함께 띄울 것.**
5. 투자 권유가 아님을 명시할 것. 이 모델은 **다음 거래일 하루**만 본다.

`registry --refresh` 를 돌렸는지 확인. 신규 상장은 레지스트리 갱신 전까지
`UnknownSymbol` 이다.

**Q. `similar` 결과에 자기 자신이 나온다**
나오면 안 된다 — 버그다. 종목코드로 제외 처리가 걸려 있다. 제보 바람.

**Q. 예측이 전부 같은 방향으로만 나온다**
`임계값` 을 확인할 것. 0.5 로 비교하고 있을 가능성이 높다 (4절 참조).

**Q. 미국 종목의 지수 수익률이 이상하다**
`registry.parquet` 의 `index` 가 NASDAQ 인지 S&P500 인지에 따라 기준 지수가
갈린다. 둘 다 상장된 종목은 S&P500 으로 잡힌다.
